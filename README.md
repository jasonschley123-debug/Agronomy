# NLAg Formulator — hostable / installable build

This folder is generated by `src/build.py` (don't edit these files by hand). It is the same app as the single-file
`index.html`, plus what a phone needs to **install** it and open it **offline**:

| File | What it is |
|---|---|
| `index.html` | Passcode lock screen + the whole app **encrypted** (AES-256-GCM, key = PBKDF2-SHA256 600k of the passcode). Only readable after unlock |
| `manifest.webmanifest` | App name, colours (navy #003DA5 / lime #8EC63F), icons, standalone display |
| `sw.js` | Service worker: caches the app shell for offline use; map tiles, field borders and imagery stay online-only |
| `icons/` | 192/512 px icons, a maskable 512 px icon, the iPhone home-screen icon (180 px) and a 32 px favicon |

## Building (passcode required)
The hosted build is always encrypted. Build with the passcode in the environment (never on the command line, never in a file):
`/workspace/.venv-nlag/bin/python src/build.py` (needs the `cryptography` package). If `NLAG_APP_PASSCODE` is not set,
the build refuses, deletes any stale `deploy/` folder and only writes the local single-file `../index.html` (unencrypted, for
local use only; don't host that one). Details: `docs/PASSCODE-LOCK-2026-09-26.md`.

## Hosting
Upload the folder's contents as-is to any static **https://** host (GitHub Pages, Netlify, Cloudflare Pages, S3 +
CloudFront…). No server code is needed. HTTPS is required: browsers only allow live GPS (Drive mode), the service
worker and "install" on secure origins. Opened from a file (`file://`) the app still works, but Drive mode can't
track you and it can't be installed.

## Installing on a phone
* **Android (Chrome):** open the https link → the app shows **⬇ Install app** next to Drive mode (or ⋮ › Install app).
* **iPhone (Safari):** open the https link → Share › **Add to Home Screen**.

## Updating
Rebuild (as above) and upload again. `sw.js` carries a content hash, so phones pick up the new version the
next time they open the app with signal.
